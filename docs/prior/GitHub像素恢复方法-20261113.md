## 1. SpriteGrid：先检测网格周期与相位

仓库：[marksverdhei/spritegrid](https://github.com/marksverdhei/spritegrid)。本次主分支提交为 `64ab6f38b914d8e4bc7db681a541c898b876a1b1`。

核心流程读取水平、竖直梯度投影，检测峰间距，再以置信度和网格比例检查排除部分不可信结果；相位函数在一个周期内寻找最强梯度对齐位置。低置信度可返回零网格。来源：[detection.py](https://github.com/marksverdhei/spritegrid/blob/64ab6f38b914d8e4bc7db681a541c898b876a1b1/src/spritegrid/detection.py)。

恢复时按检测周期布置采样中心，并对中心附近核取代表色。需要注意：README描述几何中位数，但本次 `create_downsampled_image` 默认 `median_type="naive"`，调用方未覆盖，实际默认逐通道中位数（`np.median(..., axis=0)`）；不能照搬README宣称当前默认就是几何中位数。量化参数是每通道4～8位，不等于16色或指定原版色板。Alpha在RGB量化时保留，不自动成为0/255。来源：[main.py](https://github.com/marksverdhei/spritegrid/blob/64ab6f38b914d8e4bc7db681a541c898b876a1b1/src/spritegrid/main.py)、[utils.py](https://github.com/marksverdhei/spritegrid/blob/64ab6f38b914d8e4bc7db681a541c898b876a1b1/src/spritegrid/utils.py)。

重要边界：`--res 48x64`对应的 `apply_resolution` 是对恢复结果再执行NEAREST缩放，不证明检测到了48×64逻辑网格。自动相位需明确启用 `--auto-offset`；否则调用默认相位为0。README还提供动画共享网格，但本轮未深入验证该分支。来源：[README](https://github.com/marksverdhei/spritegrid/blob/64ab6f38b914d8e4bc7db681a541c898b876a1b1/README.md)、上述main.py。

**适用判断（本研究推论）：**适合本来就存在较稳定重复像素周期、仅有噪声和小偏移的生成图。若不同零件采用不同像素粒度、边界完全不共格，就没有一个全局周期可恢复。中位数可压掉噪声，也可能丢失小于采样核主导面积的细线；最终仍需检查管路、支撑和高光，不因置信度通过就宣告美术通过。

## 2. SpriteFusion Pixel Snapper：允许局部切格偏移，再取格内众数

仓库：[Hugo-Dz/spritefusion-pixel-snapper](https://github.com/Hugo-Dz/spritefusion-pixel-snapper)。本次主分支提交为 `02f9315d73d3219274d17767b36d9a231a6b1f4b`，`src/lib.rs` blob为 `92a0dec453fa90e11a85a5495ce9319efafd06cc`。

源码先量化分析图，再计算灰度梯度行列投影，以峰距中位数估计步长。`walk`在预计下一条边界附近寻找强梯度，因此不是始终固定间距的采样；随后两轴交叉稳定切点。`resample`对每个切分格内的完整RGBA计数，以出现次数最多的RGBA作为一个输出像素，最后可映射到用户指定色板。来源：[lib.rs](https://github.com/Hugo-Dz/spritefusion-pixel-snapper/blob/02f9315d73d3219274d17767b36d9a231a6b1f4b/src/lib.rs)。

README支持手动像素步长覆盖和自定义HEX色板。其“AI模型不能理解网格”的表述是项目作者的概括，本研究不当作对所有模型的证据。源码在弹性遍历处直接注释可能出现形变，说明自动对齐不是无损恢复承诺。来源：[README](https://github.com/Hugo-Dz/spritefusion-pixel-snapper/blob/02f9315d73d3219274d17767b36d9a231a6b1f4b/README.md)、上述lib.rs的walk/resample。

**适用判断（本研究推论）：**当像素块大致有周期，但有轻微漂移或大小不均时，它比严格均匀网格提供另一种假设。代价是不同宽度的源区域压成同一目标像素，可能改变细部比例；格内众数也会舍弃面积少的细管、窄高光。固定原版色板能约束输出颜色，不能恢复被舍弃的结构，也不能决定某个亮点是不是合理的螺钉。

## 3. Pixel Art Resampler：把准确W×H作为转换基线

仓库：[jiwoo7158/pixel-art-resampler](https://github.com/jiwoo7158/pixel-art-resampler)。本次主分支提交为 `fb4e9fc1f7798ebb52458860df6788bb76b08866`。

它没有先证明存在隐含像素网格，而是直接创建指定宽高canvas，按Contain/Cover/Stretch及对齐方式映射源区域，然后用Nearest、中心采样、双线性或面积平均取色。面积平均支持预乘Alpha，随后可用逐通道量化、K-means或固定HEX色板；抖动可关闭。来源：[README](https://github.com/jiwoo7158/pixel-art-resampler/blob/fb4e9fc1f7798ebb52458860df6788bb76b08866/README.md)、[main.js](https://github.com/jiwoo7158/pixel-art-resampler/blob/fb4e9fc1f7798ebb52458860df6788bb76b08866/js/main.js)。

两个易误读的源码细节：Alpha阈值只把低于阈值的像素设为透明，并未把其他Alpha统一设为255；K-means对不重复RGB进行聚类，未按原像素面积频次加权，因此其色板可能受大量小面积渐变色影响。来源：上述main.js的processBitmap、extractKMeansPalette。

README明确说明该工具不能自动产生好的游戏精灵，复杂构图缩小会丢信息，K-means实现也不等同专业像素工具的调色板编辑。它适合做一个“准确尺寸已经满足，但结构损失多少”的基线，不适合宣称找回了作者或生成模型的真实像素网格。

## 对矿化机可操作的实验建议

下面仅为实验设计，尚未执行；其结果必须与直出实验分开记账。

1. **先做阳性对照。** 用已有原版小精灵制作已知整数最近邻复制图，记录原点和倍数，再分别尝试恢复。逐像素RGBA应能对回原图；这是方法正确性的测试，不是新素材制作。
2. **固定同一矿化机输入。** 用用户认可的v3造型作为结构观察基线，v4作为透明问题样本；不要一边换造型一边换恢复算法。v4大量主体半透明，不能简单假设Alpha阈值就会修好。
3. **先报告检测结果，不强制48×64。** 记录横纵周期、相位、置信度和自然输出尺寸。特别检查左右半幅、上中下分区的周期是否一致；不一致时应承认没有可信的全局网格。
4. **最多比较三种有解释的路径。** A：均匀周期／相位＋中心核中位数；B：弹性切格＋RGBA众数；C：直接48×64面积采样／中心采样基线。使用同一原版固定色板、关闭抖动，避免算法间同时改变多个条件。把检测、取色、palette步骤单独记录。
5. **先评结构，再评色数。** 检查料斗收口到培养筒是否连通、支座是否承托、右侧水管是否断裂、托盘嘴是否保留、金属亮边厚度是否均匀；按原生尺寸判断。色数和Alpha合格不能替代这些检查。
6. **记录需要人工修整的范围。** 对断管、糊掉的接缝、消失的短亮段逐项标记。若需重新设计大部分结构，应把路线判为不适合本输入；不能用大量手修掩盖自动恢复失败。

## 对“直接生成”的启示

这三个项目共同处理的是生成图往往缺乏严格格点约束的问题，提供的是后处理，不是原生小图生成的证明。它们提示可以单独研究“生成图是否含有可稳定恢复的网格”，但用户目标仍是直出时，这只能是诊断或备用路线。最有价值的下一项生成实验，是固定造型与参考，只改变网格／平涂约束，测量自然周期是否更一致；不是仅把输出变成48×64就宣布达到原版品质。
