# 当前内置生图工具：直出精灵能力边界

2026-11-13。仅核对当前会话工具接口、本地随附技能和已有输出；没有新生图、联网查证或安装。结论不推广到其他图像模型或API。

## 接口事实

本会话 `image_gen__imagegen` 公开参数只有 `prompt`、`transparent_background`、`referenced_image_paths`、`num_last_images_to_include`，没有结构化的宽度、高度、输出尺寸、调色板或Alpha二值化参数。因而“48×64”“16色”“Alpha仅0/255”在本次调用中都只是提示词目标；无法通过该接口把它们设置成文件格式层面的硬约束。透明背景有专门布尔参数，但该参数不承诺整个可见主体全部不透明。

接口来源：当前会话开发者提供的 image_gen 工具声明，无法提供外部固定URL。

随附 imagegen技能（本机技能说明，不随公开归档分发） 要求默认使用内置工具、透明请求开启真实透明输出并保留生成Alpha、实际检查输出；普通尺寸控制不得擅自改用CLI。其CLI章节不是内置接口规格，本研究不据此推断内置工具分辨率上限或下限，也不据此推荐未经验证的API路径。

## 能下的结论

- 本次四轮没有实现48×64原生尺寸直出；加强“实际尺寸、不要预览”等文字没有解决这个问题。
- 透明参数在本例有效地产生了Alpha通道及透明背景，但没有同时保证硬边和全不透明主体。
- 提示词中的逻辑网格、平涂、色数仍需独立测量，不能凭尺寸比例、图像观感或提示词文字判定通过。
- 当前接口缺少尺寸硬参数，意味着**不能承诺**精确原生尺寸直出；不是证明该模型永远不可能偶然给出目标尺寸。
- 当前现象既不能证明所有图像模型都无法小尺寸直出，也不能证明所有原版精灵必须手绘或经过缩放。

## 未知项与下一步实验边界

底层模型、输出尺寸选择机制、1086×1448是否受参考图或内部后处理影响、透明处理是否改变全图Alpha，当前接口与已有证据均未说明。不能归因于某个模型内部环节。

下一步应将“结构造型接近原版”“严格平涂和网格”“透明边缘”“实际文件尺寸”四项分别记录。一次只改一个主要变量，固定参考与构图，避免把造型变好误报为格式合格。尺寸若仍固定输出大图，应将其作为未解决的接口能力限制，不反复把提示词强调当成确定的解决方案。任何缩放、量化或Alpha阈值化都属于后处理实验，不能计入直出成绩。
