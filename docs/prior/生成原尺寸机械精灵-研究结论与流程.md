# 接近原版机械风格的原尺寸精灵：研究结论与流程

2026-11-13。目标是生成接近深空当铺原版机械品质、具有对应实际尺寸的精灵。主要依据公司GitHub的原版参考与结构/高光研究，以及三个公开GitHub恢复工具的源码经验；允许本地工具。此记录覆盖本次实验与矿化机交付，不宣称图像模型已能稳定直出精确小尺寸精灵。

## 结论

本次可落地的路线是：**用生成图确定造型，在明确画布上做确定性尺寸/颜色转换，再在原生尺寸整理结构与材质。** 已在48×64矿化机上完成实例，PNG和分层Aseprite源稿见矿化机目录J记录。用户已选择保留v5造型继续细化材质；v6按此方向完成。

纯提示词直出在已测入口未满足要求。指定48×48/48×64没有控制实际输出尺寸，精确调色板和单色平涂要求也未保持准确RGB。最简单三块红绿蓝样本内部仍有24～68种RGB，指定颜色命中0%；这说明问题不能只归因于复杂机械或透明背景。不能据最终PNG定位模型、解码还是交付环节导致偏差，也不能推广为所有入口必然失败。

## GitHub经验如何用于本地流程

- [SpriteGrid](https://github.com/marksverdhei/spritegrid/tree/64ab6f38b914d8e4bc7db681a541c898b876a1b1)：周期和相位检测适合确有统一网格的输入；其指定分辨率选项包含恢复后再缩放，不能当作检测出真实目标网格的证据。
- [SpriteFusion Pixel Snapper](https://github.com/Hugo-Dz/spritefusion-pixel-snapper/tree/02f9315d73d3219274d17767b36d9a231a6b1f4b)：弹性切格及格内代表色提供处理漂移的思路，但可能改变局部比例、吞掉细线。本地H基线只修复少量孔洞间隔，未充分解决炉子结构丢失。
- [Pixel Art Resampler](https://github.com/jiwoo7158/pixel-art-resampler/tree/fb4e9fc1f7798ebb52458860df6788bb76b08866)：指定尺寸采样与固定色板适合作为可量化转换基线，不能保证转换后就是好的精灵。

详见GitHub像素恢复方法-20261113.md，包含第一方源码链接与README/实现差异。本地实现没有下载执行这些仓库代码，也没有冒称复现其完整算法。

## 后续机器的执行顺序

1. **确定原生布局和主参考。** 先记录真实W×H、功能零件及连接关系；本例48×64，结构参考为已认可矿化机造型与MOD卷烟机。材质参考可单独选。区分机器purifier和便携portable_water_purifier。
2. **生成阶段只验造型与信息预算。** 目标网格、孔洞数、短高光等可写入提示，但每项都要实测。本次G画出了九列格栅，却没让它们落在准确坐标上。不要将提示文本当成输出事实。
3. **保留原始输出，先诊断。** 测实际尺寸、Alpha、色板命中和目标网格一致性。若不存在可信网格，称为尺寸转换，不能称无损恢复。优先用已知原版整数放大图做恢复正对照。
4. **最多比较少量明确采样方法。** 本例中心采样与中心区域众数各有取舍。以管路、支撑、窗框和高光的保留情况选择；色数、尺寸和Alpha满分只是文件约束，不是品质证明。
5. **原生网格整理是明确的制作阶段。** 单独图层记录改动。先修接合暗区、线宽和部件分面，再整理金属高光。原版范例强调二维色块：短亮面、邻接暗带、端部收束，而非每个边缘统一刷白。
6. **交付与复核。** 原尺寸PNG、编辑源稿、参考色板来源、采样参数及像素修改清单一起保留。逐像素核对Alpha、色板、修改范围与源稿重新导出。引擎导入时再按项目检查Point过滤、图集压缩、枢轴和显示比例。

## 本次交付与能力边界

最终矿化机PNG为48×64，23种可见色，Alpha只含0/255，源稿重新导出RGBA差异为0。外轮廓与自动转换稿相同，用户确认保留造型后的材质细化不改变透明掩膜。

从自动稿到最终稿净改422个主体像素，占33.71%。因此，当前证据支持“生成辅助＋确定性转换＋原生整理”这一流程；不支持“完全自动直出原版品质”，也不支持“任意大图缩小即可”。后续若要求无人修整，应作为新的能力实验，不能把本例手工贡献隐去。

局部生成失败时，不建议无限追加同义提示、无限扫描采样参数。先判断是造型生成已改错结构，还是采样损失现有细节；前者需改变原生设计，后者才值得尝试网格恢复。
